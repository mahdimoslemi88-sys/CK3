# پیشنهاد قابلیت‌ها و ایجنت‌های جدید برای «وزیر بزرگ»

> سند پیشنهادی — مبتنی بر زیرساخت فعلی (`extract_save.py` → `state_report.json` با ۱۳ بخش
> و بلوک `quality`)، ۷ اسکیل داده‌محور و ۹ اسکیل دانشی در `.agents/skills/`.
> اعداد نمونه از آخرین سیو: بازی ۹۴۳/۷/۲۵ — ۸۶ جنگ فعال، ۲۲۰ فکتون، ۲۳۸ شخصیت مپ‌شده،
> ۵ شهرستان دامین، ۱۱ قرارداد رعیت، ۲۹۴ صفت در `traits_lookup`.

---

## ۱) وضعیت فعلی — نقطهٔ شروع

**داریم:**
- استخراج تک‌مرحله‌ای و ساختاری (بدون Regex سراسری) با خروجی ماشینی‌خوان و گزارش فارسی
- بلوک `quality` با `counts`، `missing_fields`، `warnings`، `sources` — پایهٔ «دادهٔ صادق»
- ۷ اسکیل داده‌محور که مستقیم از مسیرهای JSON می‌خوانند و ۹ اسکیل دانش بازی

**نداریم (مرزهای صادق فعلی):**
- ارزش نظر (opinion) شخصیت‌ها — در `active_opinions` فقط مالک/هدف هست، نه عدد
- دسیسه، راز، اوراق فشار (hooks)، اتحاد، نامزدی، لایف‌استایل و پرک، شکوه سلسله
- غیرقابل‌حل در این فرمت سیو: `player.faith`، سطح buildingها، rally points، نگاشت سطوح قرارداد

---

## ۲) اصول مشترک — برای همهٔ ایجنت‌ها (فعلی و آینده)

این هفت اصل باید در `vizier-workflow.md` و سرِ همهٔ اسکیل‌های داده‌محور ثبت شود:

1. **اول `quality`، بعد تحلیل** — هیچ ایجنتی قبل از خواندن `missing_fields`/`warnings`/`counts` نتیجه ندهد.
2. **هر عدد با مسیر JSON** — عددِ بی‌منبع ممنوع؛ شمارش دستی ممنوع، `quality.counts` مرجع است.
3. **برچسب منبع روی هر ادعا** — «سیو» / «ویکی» / «نامطمئن»؛ خلط این سه ممنوع.
4. **null ≠ صفر** — دادهٔ غایب یعنی «قابل ارزیابی نیست»، نه صفر و نه بد.
5. **قالب پاسخ واحد** — هشدارهای فوری ← تحلیل موضوعی ← حداکثر ۳ اقدام مرتب با هزینه/اثر.
6. **فارسی یکدست** — با واژه‌نامهٔ `ck3-persian-terminology`.
7. **جدول تصمیم‌گیری عددی در هر حوزه** — الگوی فصل ۸ راهنما: شرط عددی + مسیر JSON + اقدام.

## ۳) ارتقای ایجنت‌های فعلی (بدون تغییر کد استخراج)

| اسکیل | قابلیت پیشنهادی | پیش‌نیاز |
|---|---|---|
| `ck3-alert-priorities` | هشدارهای روندی («فکتون X در دو سیو اخیر ۴۰٪ قوی‌تر شده») + برای هر هشدار یک اقدام مشخص، نه فقط «مراقب باش» | اسنپ‌شات‌ها (فاز ۱) |
| `ck3-realm-analysis` | نسبت‌های ترکیبی: `vassal_power_value / total_strength`، `domain_count / domain_limit`، «امتیاز سلامت قلمرو» از ترکیب کنترل/توسعه/درآمد | ندارد |
| `ck3-economy-strategy` | رتبه‌بندی holdingها بر اساس `income`؛ «مدت تحمل بدهی» = `gold ÷ کسری ماهانه`؛ توصیهٔ ساختمان بر اساس نوع موجود (سطح صادقانه `unknown`) | ندارد |
| `ck3-military-strategy` | تحلیل ترکیب MAA (کمبود پیاده/سواره/محاصره)؛ نگاشت شوالیه‌ها به نام و صفات رزمی با `traits_lookup`؛ فهرست جنگ‌های فعال همسایگان از `wars[]` | ندارد |
| `ck3-factions-civil-wars` | نسبت `power/power_threshold` برای هر فکتون؛ رفع نام رهبر/اعضا از `characters[]`؛ فکتون‌های بی‌threshold به‌عنوان «خطر اثبات‌ناپذیر» جدا شوند | ندارد |
| `ck3-succession-realm` | پروندهٔ هر وارث از `characters[]` (سن، صفات، استرس)؛ اعلان تغییر خط جانشینی بین دو سیو؛ مرز صادق: `algorithm_recomputed=false` | اسنپ‌شات‌ها |
| `ck3-diplomacy-strategy` | فعلاً محدود به خانواده؛ برای اتحادها و نامزدی‌ها نیازمند مرحلهٔ ۵ — تا آن زمان صادقانه «قابل ارزیابی نیست» | مرحلهٔ ۵ |

## ۴) ایجنت‌های جدید پیشنهادی

### آمادهٔ ساخت از امروز (فقط اسکیل + دادهٔ موجود)

**۱. تحلیل‌گر روند (ck3-trend-analyst)**
با هر استخراج، یک اسنپ‌شات از `state_report.json` در `reports/history/` ذخیره شود؛ این ایجنت
دو اسنپ‌شات آخر را مقایسه می‌کند: روند درآمد و طلا، قدرت فکتون‌ها، جنگ‌های تازه/تمام‌شده،
تغییر خط جانشینی، افت `county_control`، تغییر قوانین. ارزش: پاسخ‌ها از «وضعیت الان» به
«جهت حرکت» ارتقا می‌یابند — مهم‌ترین پرش کیفی ممکن با کمترین هزینه.

**۲. نگهبان داده (ck3-data-steward)**
بعد از هر استخراج: اعتبارسنجی schema (تست مسیرهای اسکیل‌ها در برابر JSON)، کنترل افت کیفیت
(`characters_unmapped > 0`، `missing_fields` تازه)، تشخیص تغییر نسخهٔ بازی و هشدار
«اعداد ویکی ممکن است کهنه باشند». مالک قرارداد مسیرهای اسکیل↔JSON است.

**۳. ارزیاب تصمیم (ck3-decision-evaluator)**
کاربر تصمیم می‌دهد («با X جنگ کنم؟»، «قرارداد رعیت را سخت‌تر کنم؟»)؛ ایجنت طرف‌های
مثبت/منفی را فقط از دادهٔ اثبات‌شدنی + دانش ویکی می‌سازد، به هر طرف برچسب اطمینان می‌زند،
و صریح می‌گوید چه داده‌ای برای قطعیت لازم است — جای شبیه‌سازی را حدس نمی‌گیرد.

### نیازمند «مرحلهٔ ۵» استخراج (اول داده، بعد ایجنت)

**۴. کارشناس دسیسه و دربار (ck3-intrigue-court)** — دسیسه‌های فعال، رازها، اوراق فشار،
عامل‌ها، کارایی دارنده‌گان منصب دربار. بدون بلوک‌های `schemes/secrets` ساختنش = حدس.

**۵. معماری‌دار سلسله (ck3-dynasty-architect)** — شکوه سلسله، خاندان‌ها، درخت‌های legacy،
برنامهٔ بلندمدت خون و ازدواج راهبردی. اسکیل دانشی `dynasty-renown-legacies` داده‌محور می‌شود.

**۶. تحلیلگر دربارهای خارجی (ck3-foreign-realms)** — نیمه‌آمده: جنگ‌های فعال همسایگان از
همین الان در `wars[]` هست؛ اتحادها و قدرت واقعی دربارها با مرحلهٔ ۵ کامل می‌شود.

---

## ۵) مرحلهٔ ۵ پیشنهادی استخراج (فقط ساختاری، مثل مراحل ۱ تا ۴)

| داده | بخش JSON جدید | ایجنت فعال‌شده |
|---|---|---|
| دسیسه / راز / اوراق فشار | `schemes[]` | کارشناس دسیسه و دربار |
| اتحاد / نامزدی | `alliances[]` | تحلیلگر خارجی، دیپلماسی |
| همسرِ اعضای خانواده (مجرد/متأهل) | `characters[].spouse` | دیپلماسی، معماری‌دار سلسله |
| لایف‌استایل / پرک / تحصیل | `characters[].lifestyle` | جانشینی (تربیت وارث) |
| شکوه سلسله / خاندان‌ها | `dynasty{}` | معماری‌دار سلسله |
| گنجینه / اشیاء (بلوک ریشهٔ `inventory` همین حالا هست) | `artifacts[]` | تحلیل قلمرو |

نکتهٔ صادقانه: اگر ارزش opinion در هیچ بلوکی ذخیره نشده باشد، «رضایت رعایا» برای همیشه
غیرقابل محاسبه می‌ماند و اسکیل‌ها باید همین را بگویند — نه عددی بسازند.
